# Claude Code hooks

Hooks are wired in [`../settings.json`](../settings.json) and linked into
`~/.claude/hooks/` **file by file** by `install.ps1` - not as a whole directory,
so hooks that other tools drop in there (plugin self-healers and the like) are
left untouched.

Hook commands run through Git Bash on Windows, so paths in `settings.json` use
`$HOME/...` rather than a hardcoded `C:\Users\<me>\...`.
That keeps one `settings.json` working on machines with different usernames.

## herdr agent state (`herdr-agent-state.ps1`)

A `SessionStart` hook that reports the Claude session id (and transcript path) to
the Herdr pane it's running in, so Herdr can label the pane and track agent state.
Outside Herdr it exits immediately - it bails unless `HERDR_ENV=1` and
`HERDR_PANE_ID` are set.

**This file is generated by Herdr**, via `herdr integration install claude`.
It's committed here so a fresh machine gets a working hook straight from
`install.ps1`, without having to run the integration installer.

Consequences worth knowing:

- The header carries `HERDR_INTEGRATION_VERSION`. Run `herdr integration status
  --outdated-only` now and then; if it flags claude, run
  `herdr integration install claude` and commit the rewritten file.
- That installer also rewrites the `settings.json` hook entry with an absolute
  path. Put `$HOME/...` back before committing, or the config stops being
  portable.
